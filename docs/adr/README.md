# Architecture Decision Records

An Architecture Decision Record (ADR) captures one significant design decision: the context, the options considered, the decision and its consequences. ADRs support Chapter 3 and Chapter 4 of the FYP reports ("why the system is designed this way") and interview preparation.

Decisions that depend on the literature cite their sources. Decisions that depend on observed data cite the check, its numbers and the engineering log entry.

ADRs are drafted by Claude; the student must be able to explain each decision and the rejected alternatives.

## Status values

Proposed → Accepted → Superseded by ADR-NNNN (or Deprecated). An accepted ADR is not edited except to change its status; a changed decision gets a new ADR.
